# 全国乡村片区化数据库

统计中国大陆 31 个省级单位**县/区以下**设立「片区」推进乡村振兴的实践，建成可核验、可查询、可重建的结构化数据库。

一句话说清它现在是什么：**一个以浙苏鲁为重心的抽样库，政策全文层已经很厚，片区实体层还远未铺满。**

## 二、报数字之前必须选口径

这个库有**三个不同的「片区数」**，用途完全不同。说「有多少个片区」而不指明口径，等于没说。

| 口径 | 数量 | 含义 | 能回答什么 |
|---|---|---|---|
| **主统计**（A+B） | **471** | 成立时间在 2022–2026 窗内或判为延续至今，且有 `primary`/`support` 政策依据 | 政策分析、年份序列、跨省比较只能用这个 |
| 宽统计（A+B+C） | **658** | 同上但含时间不详 | 不得进年份分布 |
| 全量库（在册非待核） | **902** | 所有在册片区 | 只用于说明采集规模，**不得当结论基数** |
| **宏观层 M** | **1353** | 命名单元 = `area` + `belt` 去跨表重名 | 只看各省量级与分布，**不得当政策依据数** |

口径定义在 [`docs/01-概念界定.md`](docs/01-概念界定.md) §10–§11，落地为视图 `area_caliber` / `macro_unit`，
`scripts/health_report.py` 每次重算。

**跨层相减没有意义**：M 减主统计的差额不是「质量差的片区」，而是「证据强度不足但确实被这样称呼的单元」。

## 三、地域分布很不均衡（用之前必须知道）

命名单元量级：浙江 390、山东 202、江苏 83、广东 44、福建 34……最低是青海 3、宁夏 5、新疆 5、西藏 5、内蒙古 6。

这不是发展水平差异，是**采集覆盖差异**：有公开省级名单的省采得深，没有的省采得浅。
青海 3 个不代表青海只有 3 个，只代表我们只采到 3 个。

县级覆盖：2856 个县级单位里有 **626 个**有片区建档（21.9%）。分省建档率从浙江 92%、山东 67%
一路降到四川 6%、新疆 1%。

> 县覆盖有两个口径：534 是「**见到过这个名字的县**」（含仅因 `status=待核` 记录才计入的县）；
> 只算可信记录是 **474**（16.6%）。差别来自 152 个只有待核记录的县，报数时必须说明用哪个。

政策层反而覆盖 31 省全覆盖——**证据侧厚、实体侧薄**，是这个库当前最基本的不平衡。

## 四、目录结构

```
├── CLAUDE.md              # 项目约束与约定（唯一权威，改规则先看这里）
├── README.md              # 本文件
├── docs/                  # 概念界定、数据字典、采集规范、政策层、并行编排
├── data/
│   ├── raw/{ABBR}/        # 原始证据，按省两字母码分目录，只追加不覆盖
│   ├── stage/             # 采集中间产物（batches / shards / candidates）
│   ├── clean/             # 主数据 CSV（禁止手改，一切修改走脚本）
│   │   └── by_province/   # 分省分片，多人/多 agent 并行时写这里再合并
│   └── db/片区库.sqlite3  # SQLite 主库，由 build_db.py 从 clean 重建
├── scripts/               # 管线脚本（采集入库、校验、统计报告、清洗）
├── reports/               # 统计报告、QA 报告、缺口清单、试点小结
└── archive/               # 废弃版本与剔除记录，按年月归档，不删
```

数据流：`raw 证据 → stage 批次 JSONL → clean CSV → SQLite`。每一层可由上一层重建。

## 五、跑起来

依赖 Python 3.11+。所有命令在项目根目录执行。

```powershell
# 从 clean CSV 重建库（幂等）
python scripts/build_db.py

# 结构与字段校验（issues 应为 0）
python scripts/validate_db.py

# 分省分片合并进主 CSV（多人并行采集后跑）
python scripts/merge_by_province.py

# 统计报告
python scripts/health_report.py             # -> reports/qa/health-latest.md
python scripts/report_macro_layer.py        # -> reports/宏观层-分省数量.md
python scripts/report_corpus_overview.py    # -> reports/采集成果总览.md
```

政策批次入库：`python scripts/ingest_policy.py data/stage/batches/POL-{省码}{序号}-policy.jsonl`

完整命令与约定见 [`CLAUDE.md`](CLAUDE.md)。

## 六、当前进度与已知局限

**里程碑**：M0 规范、M1 试点已完成；M2 类型学仍 v0.1 未升版；M3 分批铺开名义完成但地域失衡；
M4 全覆盖未达成（青海零计入片区）；M5 统计报告、M6 地图未开始。

**四个已知局限**（用数据前请先读）：

1. **这不是全国普查，是抽样库。** 完整度由采集覆盖决定，不由现实决定。任何全国性结论都必须先声明重心在浙苏鲁。
2. **`area` 与 `belt` 的分界仍在逐条裁定中。** 现行判据是「有无官方设立动作」，且设立动作分
   名单型（`roster`）与部署型（`deployment`）两种——主统计 471 内为 170 / 301。
   两类数字在裁定完成前不得相加当总量。
3. **351 条待核不计入统计。** 其中 172 条唯一来源是媒体稿，其余卡在名称/规模/实体认定
   （判词见 `reports/qa/接手审校-2026-11-18.md`）。另有 231 个片区完全没有
   `primary`/`support` 依据（正文只提地名，仅够 `mention`）。
4. **「片区」一词在基层大量用于城市控规分区、产业园区、流域治理分区。** 这些都按
   [`docs/01`](docs/01-概念界定.md) §3 排除，不做名称匹配式收录。

**查无 ≠ 不存在**：搜不到时记为缺口清单，不改写成否定结论。缺采县清单见
`reports/gaps/coverage-gaps.md`（2026-11-18 重算：2317 个零单元县里，114 个手里已有证据文件）。

## 八、设计原则

1. **证据制准入**：无来源不入库；有线索但不达标 → `status=待核`，保留不删
2. **口径与数据分离**：库里可以放宽（有线索即留档），统计必须收紧（可比才算数）。
   口径变更只改视图与文档，不回溯改数据
3. **分层可重建**：`raw / stage / clean / db` 四层，每层可由上一层重建
4. **只摘不写**：摘要与覆盖描述一律取自原文逐字句，摘不到就留空——留空比编造一句强
5. **查无 ≠ 不存在**：用缺口清单代替否定结论
