# 08 · 并行采集编排

> 版本：v0.1（2026-10）｜依赖 `07-政策层.md`、`02-数据字典.md` §4

## 1. 并行的边界

**能并行的**：检索、抓取、正文转 Markdown、元数据抽取。
**不能并行的**：ID 分配、写 `data/clean`、`policy.instruments` 的最终编码。

这不是保守，是成本判断——一次并行冲突的清理成本远高于串行分配 ID 的那几秒。

| 动作 | 并行 | 理由 |
|---|---|---|
| 检索县/市政府网站 | ✅ | 完全独立 |
| 抓原文、转 Markdown | ✅ | 完全独立 |
| 抽 `doc_no`/`issuer`/`issued_ymd` | ✅ | 单文件事实，不需跨文件视野 |
| 编 `instruments` | ⚠️ 可并行但要复核 | 各 agent 判断尺度不同，需抽样校 |
| 分配 `policy_id`/`event_id` | ❌ 串行 | 并发会撞主键 |
| 写 `data/clean/*.csv` | ❌ 串行 | 并发写同一文件会丢行 |
| `merge` / `build_db` / `validate` | ❌ 串行 | 全局操作 |

## 2. 核心契约

```
子智能体                      主控（你）
─────────────────────────────────────────────
检索 + 抓取 + 转写
  ↓
只写 data/stage/batches/POL-{shard}-policy.jsonl
  ✗ 不碰 data/clean
  ✗ 不碰 data/db
  ✗ 不分配 ID
                              ↓
                        ingest_policy.py（串行）
                          → 分配 ID、去重、存全文、算哈希
                          → 写 by_province CSV
                              ↓
                        merge → build → validate
```

**为什么这样切**：agent 数量可以从 2 扩到 20 而主控逻辑不变。agent 的产物是纯数据（JSONL），
主控的产物是唯一权威状态（CSV/SQLite）。任何 agent 写坏都只坏自己那一份 JSONL，`--purge` 即可回滚。

## 3. 分片

分片清单由 `scripts/gen_policy_shards.py` 生成，按「县数 + 片区数」双重负载切：

```powershell
& $env:MIMO_PYTHON scripts/gen_policy_shards.py            # 全部 34 个分片
& $env:MIMO_PYTHON scripts/gen_policy_shards.py ZJ01 SD01  # 指定分片
```

产物：

| 文件 | 用途 |
|---|---|
| `data/stage/shards/{shard}-brief.md` | 直接作为子智能体的任务简报（含编码口径、契约、输出格式） |
| `data/stage/shards/{shard}-counties.csv` | 该分片的县清单 + **已有 area_id**（agent 只能引用这里的 id） |

分片由脚本自动生成：按「省 → 市」顺序把县连续切块，每片 ≤ 8 个县。
不做「整市不拆」约束——那会在市边界留下大量 1–2 县的碎片分片。

当前规模：**76 个分片 / 482 个县 / 1038 个片区**，与 `area` 表完全对齐。
每片 8 县，末片可能不足（各省级单位的尾数）。

```powershell
& $env:MIMO_PYTHON scripts/gen_policy_shards.py --list   # 只看分片清单与规模
```

**关键约束**：`{shard}-counties.csv` 的 `area_ids` 列是该分片 agent 唯一可用的片区 id 来源。
不让 agent 自己查库——一旦它绕过清单，就会造出不存在的 id，而 `validate_db.py` 会整批拦住。

## 4. 调度流程

```powershell
# ① 生成分片
& $env:MIMO_PYTHON scripts/gen_policy_shards.py

# ② 并行 spawn 子智能体（每个 agent 一个分片，简报用 shards/{shard}-brief.md）
#    主控这里同时启动 N 个，各自写自己的 JSONL

# ③ 收集后逐个入库（串行；可先 --dry-run 看解析结果）
& $env:MIMO_PYTHON scripts/ingest_policy.py --dry-run data/stage/batches/POL-ZJ01-policy.jsonl
& $env:MIMO_PYTHON scripts/ingest_policy.py data/stage/batches/POL-ZJ01-policy.jsonl
& $env:MIMO_PYTHON scripts/ingest_policy.py data/stage/batches/POL-ZJ02-policy.jsonl

# ④ 合并与校验
& $env:MIMO_PYTHON scripts/merge_by_province.py
& $env:MIMO_PYTHON scripts/build_db.py
& $env:MIMO_PYTHON scripts/validate_db.py

# ⑤ 某批质量不合格 → 回滚重来
& $env:MIMO_PYTHON scripts/ingest_policy.py --purge POL-ZJ01-policy
```

**并行度建议：单次 4–6 个 agent，硬上限 8。**

2026-10 实测：同一轮 spawn 12 个 agent 时，12 个几乎同时以
「execution ended without a terminal outcome」失败，跨了长任务与刚启动的任务两类，
是并发过载而非个别任务问题。此前 8–11 个并发可正常完成。

**失败时的抢救顺序**（已发生的部分产出不会丢，前提是 agent 有分批落盘）：

1. 先看 `data/stage/batches/POL-*.jsonl` 现存行数——已 flush 的记录仍在
2. `python scripts/ingest_all.py` 把现存产出入库（幂等，重复执行安全）
3. 只有确认没产出的分片才重新派发

**因此简报里必须要求「每确认 3–5 条就追加写入」**，这条不是形式要求：
12 个 agent 崩掉那一轮，ZJ06 保住 9 条、SD02 保住 34 条、GD01 保住 5 条，全靠分批落盘。

## 5. 关于 `instruments`：本阶段不做一致性约束

v0.1 曾把 `instruments` 的一致性问题列为"并行的真实瓶颈"，并设了硬上限与金标准。
该判断已撤回，原因见 `07-政策层.md` §0：

- `instruments` 是**描述性标签**，不是分析自变量。用同一套九类去归一化，
  会把北京「百千工程」、上海「五好两宜」、浙江「片区组团」这些地区制度差异抹平
- 采集阶段的目标是**厚度**。设上限等于主动丢弃材料
- 编码、归一、比较是语料足够厚之后的独立工作，不能在采集阶段预设框架

因此现在：**不设标签数量上限、不做跨地区归一、不设金标准**。
地方特有提法照原文记录，`validate_db.py` 对预设九类之外的标签只提示、不拦截。

`audit_instruments.py` 保留但**用途变了**：从"质量闸门"改为**盘点工具**——
列出每份文件声明了哪些标签、各自在全文的命中情况，供将来真正做编码时参考，不阻断入库。

```powershell
& $env:MIMO_PYTHON scripts/audit_instruments.py --csv reports/qa/instruments-audit.csv
```

## 6. 反模式（不要做）

| 反模式 | 后果 |
|---|---|
| 让 agent 直接写 `data/clean/*.csv` | 并发写丢行，且绕过校验闸门 |
| 让 agent 自己分配 `policy_id` | 撞主键；`merge` 后记录静默丢失 |
| 让 agent 自己查库取 `area_id` | id 幻觉，`validate` 整批拦住 |
| 一个 agent 干完一个省再下一个 | 长尾严重，一个失败阻塞全局 |
| 把 `full_text` 写成摘要 | 违反政策层硬约束，无法复核 `instruments` |
| 用官方媒体报道充当 policy 来源 | 工具编码建立在二手转述上，结论不可信 |

## 7. 质检分层

| 层 | 谁做 | 检查什么 |
|---|---|---|
| 单条 | agent 自检 | brief 末尾清单：全 `.gov.cn`、有全文、只用清单内 area_id、没编造数字 |
| 单批 | `ingest_policy.py` | JSON 合法性、`full_text` 非空、url 与 `doc_no+issuer` 去重 |
| 单批 | `validate_db.py` | `.gov.cn` 门槛、`credibility∈{A,B}`、`county_code`、字段完整性、外键 |
| 全局 | `validate_db.py` | `doc_no+issuer` 唯一、`area_policy_map` 外键、事件类型 |

`instruments` **不在任何质检层**——采集阶段不审编码。
