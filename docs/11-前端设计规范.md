# 前端设计规范（v1，2026-11-22）

> 目标：把 1 368 条片区数据做成**可引用、可核验的研究型数据库站点**，视觉上「研究机构 + 高级感」，
> 以**南开紫 + 金色**为识别色，杜绝电商感（亮色块、重阴影、圆角药丸、促销式渐变）。

## 1. 定位与读者

| 读者 | 来做什么 | 站点必须给 |
|---|---|---|
| 研究者 | 引用数字、下载数据、核对口径 | 快照日、口径卡、可复现的 CSV/GeoJSON、引用格式 |
| 政策工作者 | 找本地案例、看别省做法 | 按省/市/县筛选、类型与年份、政策原文链接 |
| 公众/媒体 | 看全貌、拿图 | 地图、分省对比、可直接引用的图注 |

设计原则：**数据优先、结论先行、口径可见**。任何图表旁边都能找到「这是什么口径」。

## 2. 品牌与色彩

| Token | 值 | 用途 |
|---|---|---|
| `--purple` | `#7E0C6E` | 主色（南开紫）：标题强调、选中态、图表主序列 |
| `--purple-deep` | `#4A0A3E` | 深色区块、页脚、悬停 |
| `--purple-tint` | `#F6EEF4` | 选中行、标签底色 |
| `--gold` | `#B08A4F` | 金色：细线、编号、强调数值、页眉下沿 |
| `--gold-light` | `#E7D6B4` | 深底上的金色文字/线 |
| `--ink` | `#1B1520` | 正文 |
| `--ink-2` | `#4E4457` | 次级文字 |
| `--ink-3` | `#8C8193` | 注释、占位 |
| `--paper` | `#FBF9F7` | 页面底色（暖白，不用纯白大底） |
| `--card` | `#FFFFFF` | 卡片 |
| `--line` | `#E9E1E6` | 1px 分隔线（主要靠线，不靠阴影） |

**渐变只用在两处**：首屏深紫渐变（`135deg, #7E0C6E → #3C0733`）与地图图例色阶。
其余一律纯色。金色只做「一笔」——页眉下沿、区块编号、关键数值的短线，不做大面积。

**深色主题**（跟随系统 `prefers-color-scheme: dark`，逐令牌定义，不用滤镜反转）：
`--paper #1E1922`（深紫灰，不用近黑）、`--card #282130`、`--ink #F0EBF1`、`--ink-2 #C6BCC8`、
`--line #3B3442`、表头 `#2F2838`、主紫 `#CF8CC3`（深底提亮）、金色 `#DEC7A0`；
地图卡片在深色下用 `#3A1733 → #180A14` 渐变，避免与页面糊成一片。

**不做的事**：首屏不放宣传语、不放情绪化大标题；标题即站名（34px 宋体），下面一行元数据。

## 3. 字体与排版

- 标题/数字：`Source Han Serif SC, Noto Serif SC, Songti SC, STSong, SimSun, serif`
- 正文/表格：`Source Han Sans SC, Noto Sans SC, PingFang SC, Microsoft YaHei, sans-serif`
- 字号阶：12 / 13 / 14 / 16 / 20 / 28 / 40 / 56（1.25 比例，数字用 tabular-nums）
- 行高：正文 1.7，表格 1.5，标题 1.25
- 中文标题加 `letter-spacing: .02em`；英文/数字不加

## 4. 栅格与页面骨架

- 内容最大宽 **1280px**，左右留白 24（桌面）/ 16（移动）
- 顶部：品牌区（左）+ 主导航（右），高 64，白底、下沿 1px 金线
- 首屏：深紫渐变块，左侧标题（宋体 40–56）+ 右侧三个关键数字（金色细线分隔）
- 内容区：卡片间距 20，卡片内边距 20–24，圆角 **6px**（不是 16），无投影或极淡投影 `0 1px 2px rgba(27,21,32,.04)`
- 表格：表头浅灰 `#F7F3F5`，行间 1px 线，行高 40，数字右对齐

## 5. 组件

| 组件 | 规格 |
|---|---|
| 导航 | 6 项：概览 / 地图 / 省份 / 检索 / 方法与质量 / 关于；当前项底部 2px 金色 |
| KPI | 宋体大数字（40）+ 小标签（12，紫灰）+ 一句口径注释（12，ink-3） |
| 标签 chip | 小圆角 4，底色 = 语义色 8% 透明度，字色 = 语义色；不用全圆角 |
| 表格 | 见上；待核行左侧 2px 赭色边 |
| 地图 | 深色底 `#2A1626`，省界白 0.5px，图例在右下；点击省弹出右侧抽屉 |
| 详情抽屉 | 480 宽，白底，顶部金色细线，字段两列 |
| 按钮 | 主按钮紫底白字；次按钮白底紫边；文字按钮带下划线 |

**语义色**（仅用于口径，不做装饰）：
- 主统计 A+B：`--purple`
- 宽统计 A+B+C：`#A85C8F`（紫的浅阶）
- 待核：`#B7793A`（赭）
- 无依据/排除：`#9A9499`（灰）

## 6. 页面规格

### 6.1 概览
- **报头（masthead）**：左侧 34px 宋体站名 + 一行元数据（快照日 · 省数 · 片区数 · 政策数）+ 三个文字链（口径/下载/引用）；右侧三个统计（命名单元 / 主统计 / 覆盖县），金色细线分隔
- **不放**宣传语、slogan、引导性大标题
- 报头下：4 个 KPI 卡（宋体数字 + 口径注释）
- 再下两栏：左「分省格局」条形图（可进地图页），右「证据强度构成」
- 再下：片区记录表（前 5 行示例 + 全部入口）
- 页脚：快照日、口径链接、引用格式、自定义域名

### 6.2 地图
- 全屏地图（省界），右上指标切换（片区数/主统计/待核占比）
- 点击省 → 右侧抽屉：9 项指标 + 「查看该省 N 条片区」按钮（跳检索并预筛选）
- 图例固定右下，灰=无记录

### 6.3 省份
- 31 省卡片墙（省名、片区数、主统计、待核占比条形）
- 点入省详情：头部 KPI + 类型/年份小图 + 该省片区表（可排序）

### 6.4 检索
- 左栏筛选（关键词、省、类型、层级、年份、证据、状态），右栏结果表
- 每行可展开详情抽屉（名称、县、类型、成立时间、证据、政策链接）
- 顶部显示「结果数 / 已选口径」，支持导出 CSV
- URL 参数可分享（`?prov=330000&type=T01`）

### 6.5 方法与质量
- 口径卡：M/P 两层、A–E 五组、证据三级，各配一句「能不能相加」
- 审计摘要：ERROR/WARN 计数与 top 检查项
- 数据边界：不收什么（示范村镇/园区/控规分区）、0 值的含义

### 6.6 关于
- 数据快照、版本、维护者、引用格式（bibtex + 中文引用）、许可与免责
- **全量下载**（用户指定放这里）：`areas.csv` / `provinces.csv` / `provinces.geojson` / `cities.geojson` / Excel 汇总包，附文件大小与字段说明；原始 `data/raw` 原文不公开

## 7. 交互与可访问性

- 键盘可达：Tab 焦点环用金色 2px；表格支持方向键
- 对比度：正文 ≥ 4.5:1；金色文字只用于深底
- 移动端：筛选折叠为抽屉；表格转卡片列表；地图可双指缩放
- 打印：隐藏导航，展开表格

## 8. 技术形态

- 多页静态：`index.html` / `map.html` / `provinces.html` / `explore.html` / `method.html` / `about.html`
- 共享 `assets/style.css` + `assets/app.js`（无框架、无 CDN，除非自托管字体）
- 数据分片：`assets/data/meta.js`、`areas.js`（1 368 行）、`summaries.js`、`geo/provinces.geojson`（634KB，fetch 加载）
- 构建：`scripts/build_site.py` 把 `web/` + 地图数据打包到 `dist/`（只含站点成品）

## 9. 部署

- GitHub Actions → Cloudflare Pages（与 `Innovation-in-Local-Government` 同款：`wrangler-action@v3`，`pages deploy dist`）
- 项目名：`rural-development`；secrets：`CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`
- 自定义域：Cloudflare Pages → Custom domains → `ruraldevelopment.jinhuazhang.top`（CNAME 由 CF 自动写入）

## 10. 验收

- 首屏 LCP < 2.5s（4G）、无阻塞第三方请求
- 6 个页面均有 `<title>`、描述与 og:image
- 地图抽屉点选与检索联动正确
- 移动端 375 宽无横向滚动
- 页脚快照日与 `docs/01` 一致（`check_doc_caliber` 覆盖）
