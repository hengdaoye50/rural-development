# 07 · 政策层采集规范

> 版本：v0.2（2026-10）｜遵循 `../CLAUDE.md`、`02-数据字典.md` §4–§5.1  
> 适用：`policy`、`area_policy_map`、`event` 三张表的采集

## 0. 定位：勘探阶段，先厚后薄

本层当前处于**探索性采集阶段**，目标是尽可能完整地把全国各县片区化的政策文本收进来，
而不是先把材料压进一个预设的编码框架。

三条纪律：

1. **不预设自变量。** `instruments` 只是描述性标签，供检索与盘点，**不作为跨地区比较的分析变量**。
2. **不抹平地区差异。** 北京的「百千工程」、上海的「五好两宜」、浙江的「片区组团」、
   江西的「四融一共」、山东的「省级片区」是多套不同的制度话语。这些差异本身就是研究对象，
   过早统一口径会把它们抹掉。地方特有提法照原样记录，不强行归类到九类之内。
3. **宁多勿漏。** 不设收录数量上限。一份文件涉及几类就记几类，不确定时倾向记录。

**唯一不可让步的是全文。** 摘录对政策层的价值接近零——后续任何编码、文本分析、
引文核对都必须回到全文。这是本层唯一严格的硬约束。

## 1. 政策层要收集什么

`area` 表只回答「哪里有片区」。政策层要留下的是**可复核的制度过程证据**：

| 关注点 | 依赖字段 |
|---|---|
| 谁在什么层级、什么时候定的 | `issuer`、`issuer_level`、`doc_no`、`issued_ymd`、`published_ymd` |
| 文件说了什么、怎么表述 | `full_text`（全文）、`doc_type`、`source_kind` |
| 涉及多少片区、多少钱 | `target_areas`、`budget_wan`（只记原文明确写出的数） |
| 文本主题的粗分类 | `instruments`（描述性，非自变量） |

## 2. `instruments` 的定位与记法

见 `02-数据字典.md` §7.1 的九类**常用标签**。要点：

- **九类是参考词表，不是封闭枚举。** 地方特有做法（如「片区组团」「强村公司」「两进两回」）
  直接按原文记入，不必硬塞进九类
- **有表述就记**，不要求达到某种「操作性门槛」；也不必因为「只是提了一句」而删掉
- **不设数量上限。** 综合性规划涉及面广是客观事实，不该被裁成 2–4 项
- 一个都识别不出时留空即可（纯名单、纯批复确实不涉及工具）
- 每个标签尽量能对到原句，方便后续复核；但**不为了对得上而删减**

> 变更说明：v0.1 曾要求「只认操作性证据、超 6 个视为失效」。
> 该口径会把综合性规划强行压平，且用同一把尺子量不同地区的文件，已废弃。

记录示例：

| 原文片段 | 记法 |
|---|---|
| 「市财政每年安排 5000 万元专项资金，对考核前 3 名片区给予奖补」 | `财政,考核` |
| 「坚持规划引领，统筹推进五大振兴」 | `规划`（记下，不必因泛泛而删） |
| 「深化'千万工程'，打造'一村一品'片区组团」 | `组织,产业,片区组团` |
| 纯名单/纯批复，无工具表述 | 留空 |

## 3. 权威来源门槛

**准入门槛**：`.gov.cn` 域名，或政府公报原件。不满足即不入 `policy` 表。

### 3.1 白名单（可入 policy）

| source_kind | 入口特征 | credibility |
|---|---|---|
| `政策文件` | 政务公开/政策文件/规范性文件栏目，有文种、有文号 | A |
| `政府公报` | 政府公报栏目，PDF 或网页版 | A |
| `部门动态` | 部门官网工作动态、通知公告、公示，无文号 | B |
| `新闻发布` | 政府网新闻发布/政策解读栏目 | B |

**这四个值是封闭枚举**（见 `CLAUDE.md` 决策日志 2026-10）。`ingest_policy.py` 只做一处同义规整
（`部门公开` → `部门动态`），其余认不出的取值会**直接报错中断该批次**，不会替你猜一个。
原因：`source_kind` 与 `credibility` 绑定，把「部门动态」硬归成「政策文件」会造出 A 级假证据。
采集时拿不准有文号还是动态，就先看页面上有没有文号——有文号的进「政策文件」，没有的进「部门动态」。

### 3.2 黑名单（禁止入 policy）

- 商业门户与聚合：`sohu.com`、`sina.com.cn`、`qq.com`/`inews.qq.com`、`163.com`、`jiemian.com`、`52hrtt.com`
- 自媒体、公众号转载、无署名聚合站
- 官方媒体（新华社、人民日报、省级党报）——**仅入 `source`，不入 `policy`**

> 当前库中 `52hrtt.com` 一家贡献 30 条 `source`（同一篇文章拆成 30 条，全标 B 级）。政策层必须堵住这个口子，否则 `instruments` 编码会建立在二手转述上。

**浙江的两条关键判据**：

1. 区县级片区设立依据最可靠的来源是**各县《「县城—中心镇—重点村」发展轴空间专项规划》**

2. 命中「片区」的结果七成是**城市控规的空间分区**（XX 片区详细规划/控规/地块），

webfetch 会拒绝，需本地下载后用 `pypdf` 抽取。

## 5. 采集单位与广度：以「县」为轴，穷尽式收集

**不要按「片区 × 一段话」采，要按「县 × 政策链条」采。** 一级文件通常覆盖多县或多片区，
按县采的边际成本远低于按片区采。

一个县的片区化政策构成多级链条，各级都要收：

```
省级   实施意见 / 发展规划 / 名单批复 / 管理办法      ← 定框架、产生片区
  ↓
市级   实施方案 / 任务分解 / 名单转发 / 考核办法       ← 加压、分解指标
  ↓
县级   片区规划 / 领导小组文件 / 实施方案 / 资金办法   ← 实体化设立（area 的直接依据）
  ↓
乡镇   项目安排 / 具体建设内容 / 现场推进              ← 落地
```

### 5.1 本阶段目标是「厚度」，不是「覆盖率达标」

不做「每县至少 1 份」这种配额式采集——那会诱导只采最容易找的一份就收手。改为：

**一个县能收多少收多少。** 同一县的相关文件不嫌多：规划、实施方案、领导小组通知、
资金管理办法、考核办法、名单批复、公示公告、验收通报、招标采购、人大建议答复，
只要涉及该县片区化，都收。同一政策链条的不同层级、不同年份版本（含已修订、已废止）也收——
文本版本序列本身就是政策演进的证据。

具体到每类文件应尽量穷尽：

| 文件类别 | 尽量收到 |
|---|---|
| 名单/批复/公告 | 每一批次都收，不要只收最新的 |
| 规划类 | 县级片区专项规划、国土空间规划涉农部分、村庄布局规划 |
| 组织类 | 领导小组、专班、联合党委、片区党委的成立与调整文件 |
| 资金类 | 专项资金管理办法、资金下达通知、奖补办法 |
| 考核类 | 考核办法、评分细则、验收标准、通报 |
| 政务动态 | 推进会、观摩、调研、挂牌、签约、评估结果 |
| 关联文本 | 招标/采购公告、人大建议与政协提案答复、审计或巡察反馈涉片区部分 |

**唯一下限**：至少把该县已入库片区的**设立依据**找到——即 `area` 记录是怎么来的。
若确实找不到，如实报告，不编造。

### 5.2 不因为「已经有一份了」就停

已入库的判断标准只有一条：`doc_no + issuer` 或 `url` 重复。除此之外，同一县多份文件一律收录。

### 5.3 实测：高产入口往往不是「政策文件」栏目（2026-10 验证）

首批分片采集后确认了一条反直觉的经验：**县级「政策文件」栏目经常是空的**，
真正带完整正文的是下面这几类：

| 高产出入口 | 为什么有料 |
|---|---|
| **人大建议 / 政协提案答复** | 答复里常写「我县已建 X 个片区、覆盖 Y 个村、2030 年前规划 Z 个」，这些口径正式文件里反而没有 |
| **政府工作报告 / 经济社会发展状况** | 正文完整，逐片列名（如「梨花水镇」「碱地粮仓」及市级片区数）。无文号 → 记 `部门动态`/B |
| **项目库入库指南** | 含项目清单与资金安排，能拿到 `budget_wan` |
| **镇街工作动态** | 落地层表述，含「抱团发展」「跨村联建」等操作性做法 |
| **招标采购公告** | 「片区规划编制」成交公告可反证该县确曾编制规划，即使正文未公开 |

**站内检索优于通用搜索引擎**：不少县级政府站对搜索引擎几乎无索引（如诸城、高密），
必须用其站内检索（常需 playwright 渲染）。

**已知失效入口**（同类分片可跳过）：正文留空的转载页、扫描件 PDF（CamScanner，无文本层）、
省级「规划计划/通知公告」栏目常无片区名单页——省级名单往往只在新闻发布会稿或转载稿中出现。

## 6. 单份文件采集流程

```
① 定位   在政务公开栏目检索到文件页，确认 .gov.cn 域名与文种
② 取全文 优先下载 PDF/附件原文；无附件则抓正文 HTML → 转 Markdown
③ 存档   建目录 + 写 meta.json + 存全文 + 算哈希
④ 抽元数据 title / doc_no / issuer / issued_ymd / published_ymd
⑤ 编码   issuer_level / doc_type / source_kind / instruments / target_areas / budget_wan
⑥ 落表   写 data/clean/by_province/{省码}-policy.csv
⑦ 挂接   写 {省码}-area_policy_map.csv，把文件与片区相连
⑧ 质检   跑 scripts/validate_db.py，issues 必须为 0
```

### 6.1 存档结构

```
data/raw/{ABBR}/{YYYYMMDD}-{slug}/
├── 原文.md          全文（不是摘录）
├── 原件.pdf         有 PDF 附件时保留原件
└── meta.json        含 policy_id, url, doc_no, issuer_level, instruments 等
```

`slug` 规则：`{省}{市}{县}-{文种}-{关键词}`，如 `sd-ly-ys-pianqu-shishifangan`。

### 6.2 全文转换要求

- 保留原文章节标题层级（`##`），便于后续条款定位
- 保留文末落款与成文日期
- 表格转 Markdown 表格（名单类文件的核心内容常在表格里）
- **不保留**导航栏、页脚、相关推荐
- 转换后记录 `full_text_chars`（正文汉字数）

## 7. 字段抽取规则与易错点

| 字段 | 规则 | 易错点 |
|---|---|---|
| `doc_no` | 原文照抄，含发文字号格式 | 「〔〕」不要写成「[]」或「()」；无文号留空，**不要写「无」** |
| `issuer` | 发文单位原文，多单位用「、」 | 区分「发文单位」与「转发单位」——转发件填原发文单位 |
| `issued_ymd` | **文末落款的成文日期** | 不是网页发布日，不是会议日期 |
| `published_ymd` | 政府网公开日期 | 二者常差数周，政策扩散分析必须用 `issued_ymd` |
| `issuer_level` | 按发文机关层级 | 省政府办公厅转发市文件 → `province`（发文层级优先） |
| `target_areas` | 文件明确写的片区数 | 「力争建成若干个」不可折算，留空 |
| `budget_wan` | 明确金额，单位万元 | 「1.2 亿元」→ `12000`；只填数值，不填单位 |
| `full_text_chars` | 正文汉字数，去空白 | 动态类通常 <500，可用于识别「只有标题的僵尸页」 |

## 8. 质检清单

每批采集后逐条自查：

- [ ] 全部为 `.gov.cn` 域名（或政府公报原件）
- [ ] `local_path` 指向**全文**，不是摘录
- [ ] `doc_no + issuer` 未与已有记录重复（同县其他文件不因「已有」而弃）
- [ ] `budget_wan` / `target_areas` 在全文里可检索到，未明示则留空
- [ ] `issuer_level='county'` 的记录 `county_code` 非空
- [ ] 找不到的县/文件已如实报告，没有编造

`instruments` 不在质检门禁内——它是描述性标签，记多记少不影响入库。

## 9. 分阶段推进

| 阶段 | 范围 | 目标 |
|---|---|---|
| P1 存量盘活 | 现有 167 条 `.gov.cn` source 中的政策文件候选 | 回填政策层，验证 schema |
| P2 全国探索性采集 | 全部 31 省、482 个有片区的县 | **穷尽式**：每县能收多少收多少，不设上限 |
| P3 补漏 | 按各批报告中的「未检索到」清单 | 换入口、换关键词二次检索 |
| P4 编码与分析 | 全库 | 待语料足够厚之后再进行，不在采集阶段预设框架 |

阶段之间不做质量收缩。P2 的产出允许冗余、允许同一主题多份文件并存——
分类与编码是 P4 的事，采集阶段只负责把材料完整带回来。

批次命名：`POL-{分片号}`（如 `POL-ZJ01`），分片见 `08-并行采集编排.md`。
