# 统计口径与数据库设计（2026-11-21）

> 这份文档回答一个问题：**在已有数据资产之上，如何把「口径」变成可计算、可审计、可复现的数据库结构**。
> 它是分析设计的纲领；具体字段定义仍以 `docs/02-数据字典.md` 为准，裁决规则以 `docs/01-概念界定.md` 为准。

## 0. 一句话结论

现有口径（A–E 五组、M/P 两层）**逻辑是对的，但还停留在「视图层 + 文档约定」**：
- 视图能算总量，但**不能表达「分析单元」**（缺少 `admin_level`、缺少县/片区两层台账）；
- 覆盖率有多个分母（县级 2856 / 名单条数 / 台账条数），**没有统一登记**；
- 证据强度只分 primary/support/mention 三档，**与「点名级/弱定位/无关联」四级实测不一致**。

因此下一步不是继续采数，而是**把口径实体化**：落 3 个字段 + 2 张表 + 1 个分析视图，让「口径」可以被 SQL 直接表达。

## 1. 研究对象与样本框

### 1.1 分析单元（unit of analysis）

| 层级 | 对象 | 载体 | 用途 |
|---|---|---|---|
| 实体层 | 一个**片区**（有设立动作的命名单元） | `area` | 主分析 |
| 象征层 | 一个**带/圈/廊**（无实体化设立） | `belt` | 补充分析，不入主统计 |
| 命名层 | 一个**命名单元**（area+belt 去重） | 视图 `macro_unit` | 量级与分布 |
| 政策层 | 一份**有 primary/support 依据**的片区 | 视图 `area_caliber` | 统计推断 |

### 1.2 纳入 / 排除（四条硬边界）

**纳入**：2022 年以来、县级及以下、有官方设立动作（名单/批复/认定 或 工作报告/规划点名）的片区化单元。

**排除四类**（本轮又实测踩到两类）：
1. 示范村 / 示范乡镇 / 精品村（对象层级不符）→ 台账记 `not_area`
2. 整县试点 / 先导区（对象为县）→ `not_area`（河南 35、甘肃 11 已判例）
3. **城市控规 / 国土空间规划的乡镇级片区**（规划分区，非乡村振兴设立）→ `not_area`（四川 10 市已判例）
4. 纯园区 / 景区 / 土地征收成片开发片区

> 判据口诀：**先问「这是哪套制度里的片区」，再问「有没有设立动作」**。

### 1.3 样本框（frame）与可推性

| 框 | 定义 | 能否算漏采率 |
|---|---|---|
| 名单框 | `province_roster` / `city_roster` 中 `matched` 的省级/市级名单 | **能**（1 − in_db/official） |
| 数字框 | `count_only`（有官方数无名单） | 不能，只能量级对照 |
| 便利框 | 政府网站可采性 | 不能，只作发现工具 |

## 2. 口径分层（已有 + 本轮补强）

### 2.1 总量口径卡（对外只报一个）

| 口径 | 定义 | 当前值 | 用途 |
|---|---|---|---|
| 主统计 A+B | 时间窗内 或 延续至今，且有 primary/support | **591** | 政策分析、跨省比较 |
| 宽统计 A+B+C | 加时间不详 | **792** | 稳健性检验，不得进年份分布 |
| 全量库 | active 且非待核 | **1149** | 只描述采集规模 |
| 命名单元 M | area+belt 去重 | **1575** | 量级与分布，须与县覆盖并列 |
| 待核 | 证据链不达标 | **326** | 不进任何分子 |

### 2.2 五组 A–E（互斥，和为全量库）

A 窗内：2022-01-01 ~ 2026-11-21（或按年）
B 延续至今：2022 前成立，2023 后有 primary/support 或 event
C 时间不详：有依据、成立时间不可考
D 口径外：2022 前成立且无延续证据（**不删记录**）
E 无依据：无 primary/support（含仅媒体稿）

### 2.3 证据强度（本轮新增：与实测 tier 对齐）

现有 `rel`（primary/support/mention）与 `audit_link_veracity` 的四级实测（core/exact/stripped/tail/place_only/missing）不一致。建议映射：

| rel | tier | 证据等级 | 口径处理 |
|---|---|---|---|
| primary/support | core / exact / stripped / tail | **强**（点名级） | 计入 A–D |
| support | place_only | **弱**（仅提地名） | 降 `mention`，不计入 |
| support | missing | 无关 | 解除挂接 |
| — | — | 媒体稿 | `status=待核` |

**待落地**：给 `area_policy_map` 加 `evidence_tier` 派生列（由 `audit_link_veracity.py` 回写），让「有依据」可量化到「点名级 N 条 / 弱定位 M 条」。

## 3. 分层维度：省 / 市 / 县 / 片区

### 3.1 现状问题

- `area` **没有层级字段**，层级靠 `report_level_distribution.py` 现推（primary 政策 issuer_level > `issuer` 关键词 > support）；
- 推法有 bug 史（直辖市、市辖区名歧义），且**不可查询**——每次分析都要重算；
- 县/片区两级台账缺失：`county_roster` 不存在，县级名单只能散在 `city_roster` 的 note 里。

### 3.2 建议结构（3 字段 + 2 表）

**字段 1：`area.admin_level`**（派生 + 人工确认）
取值：`province` / `city` / `county` / `town` / `unknown`；派生规则同 `report_level_distribution.py`；人工确认写 `admin_level_src='manual'`。

**字段 2：`area.agency_level`**（设立主体层级，与空间层级分开）
省级名单里的片区可能是县级设立（`issuer_level=county`），两个维度不能混。

**字段 3：`source.excerpt_status`**
`verbatim`（逐字命中）/ `digest`（导航性摘要，本轮 190 条）/ `missing`。

**表 1：`county_roster`**（县级名单台账）
字段：`county_code`、`roster_name`、`policy_id`、`official_count`、`in_db_count`、`status`（同省市台账五值）、`note`。
用途：把「县级名单」也变成可对账的分母——这是下一个覆盖率增长点。

**表 2：`evidence_debt`**（证据欠账）
字段：`entity_type`、`entity_id`、`debt_type`（excerpt_digest / dead_snapshot / no_primary / name_unverified）、`count`、`last_seen`。
用途：把 WARN 变成可跟踪的任务单，而不是报告里的一段话。

**视图：`v_analysis_area`**（分析主表，一行一区）
字段：area_id、name、省/市/县名与码、admin_level、agency_level、type_code、setup_kind、founded_ymd、precision、caliber_group、in_main_stat、evidence_strength（强/弱/无）、n_policies、n_sources、scale_villages、issuer。
用途：所有对外分析的唯一入口，避免每次写口径 SQL。

## 4. 覆盖率与分母

### 4.1 三个分母，必须分别登记

| 分母 | 值 | 来源 | 用法 |
|---|---|---|---|
| 县级单位 | 2856 | GB/T 2260（`region` 县级行） | 县覆盖率 |
| 省级名单条数 | 各省 `official_count` | `province_roster` | 省名单漏采率（仅 matched） |
| 市级名单条数 | 各市 `official_count` | `city_roster` | 市名单漏采率（仅 matched） |

### 4.2 两个覆盖率，必须并列报

- **见到名字的县**（含待核）：约 640/2856 ≈ 22%——上限
- **有可信记录的县**（非待核）：约 490/2856 ≈ 17%——下限

> 只报一个数必然误导；`docs/09` 已规定并列，但报告脚本仍常只印一个，应改为统一模板。

### 4.3 漏采率公式（只在 matched 上算）

```
漏采率 = 1 − in_db_count / official_count
```
仅当 `status='matched'` 且 `official_count>0`；`partial` 只报差值并注原因；`count_only` 不得算。

## 5. 变量清单（面向未来回归/比较）

| 变量 | 字段 | 完整率 | 备注 |
|---|---|---|---|
| 类型 | `type_code` T01–T08 | 高 | 单值，需 `type_primary_note` 记录混合 |
| 设立方式 | `setup_kind` roster/deployment | 中 | 477 deployment、218 roster、其余 unknown（需补） |
| 层级 | 待建 `admin_level` | — | 现为派生 |
| 时间 | `founded_ymd` + `precision` | 中 | 未填集中在早期批次 |
| 规模 | `scale_villages` / `scale_towns` | 低 | 污染已清，但填得少 |
| 资金 | `policy.budget_wan` | 低 | 仅有少数政策 |
| 政策工具 | `policy.instruments` | 中 | 开放词表 |
| 证据强度 | 待建 `evidence_tier` | — | 来自 link-veracity |

## 6. 已知偏误与校正

1. **便利抽样**：早期按「政府网站可采性」采集 → 用名单框校正（matched 省可算漏采率）。
2. **媒体稿偏多**：326 条待核中多数唯一来源是媒体 → 不得进主统计；升级靠 `.gov.cn` 原文。
3. **名单不公开省**：江苏 40、浙江 200、广东 130（省级）不整体公开 → 台账记 `count_only`/`partial`，不得用声明数当分母。
4. **口径混淆两类高发**：四川「国土空间规划乡镇级片区」、河南「整县先导区」→ 均 `not_area`，已入判据。
5. **县覆盖多口径**：同一库曾出现 534/464/459 三套 → 以 `area.county_code` 为主、`area_region_map` 校验。
6. **跨县 R10**：同一片区按县分建后行数 > 名单条数（连云港 3→4）→ 台账 `official_count` 与 `in_db_count` 需注明口径。

## 8. 判定「数据库搭好了」的标准

1. 任何覆盖率/总量数字，都能用**一条 SQL** 从 `v_analysis_area` 复现；
2. 任何「有依据」的判断，都能追到 `evidence_tier` 与快照哈希；
3. 各省/市/县名单台账的 `official_count` 与 `in_db_count` 可对账，漏采率只在 matched 上算；
4. `validate_db` issues=0、`audit_data_quality` ERROR=0、`check_doc_caliber` 全部一致——三者同时成立；
5. 新增一个省/市的数据，只需「采集 → 台账 → 候选表 → ingest」四步，不需要改口径代码。
