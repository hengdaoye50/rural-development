# 片区类型学修订方案（v1，2026-11-24）

> 起因：现有 `type_code`（T01–T07）把「命名方式」「功能主题」「组织形态」三类维度压进一个字段，
> 既表达不了多主题片区，也让统计图失去解释力。本文先梳理文献，再给出可落地的多维编码。

## 一、现有 T 码的问题

| 现状 | 问题 |
|---|---|
| T01 示范片区 / T04 产业片区 / T05 农文旅 / T06 帮扶协作 / T07 城乡融合 | 混了「命名」（示范/产业）与「主题」（文旅/城乡融合） |
| T02 联合党委 | 这是**组织形态**，不是主题 |
| T03 示范带 | 已按口径迁入 `belt`，`area` 里只剩 5 条，编码空转 |
| 单值字段 | 一个片区只能有一个主题，但现实里普遍「产业+文旅+治理」叠加 |
| 分布失衡 | T01 742、T05 358、T04 204、T02 68、T07 20、T06 1、T03 5 |

一句话：**T 码不是类型学，是历史遗留的标签桶。**

## 二、文献给了哪些划分维度

**1. 郭红东（2026）《探索乡村片区组团发展新路径》，《国家治理》2026 年第 11 期**
<https://www.aisixiang.com/data/178490.html>

给出两组可直接落库的维度：

- **组合方式**：横向组合（村村联合）、纵向组合（村企联合、村社联合）、纵横交互组合；
- **组合质态**：外延性组团（侧重规模与空间扩张）、内涵式组团（侧重集成与优化创新）。

以及四类共性机制（组织创新、产业协同、治理重构、利益联结）与建议的主题分类：
**党建引领型、产业联动型、文旅融合型、生态优先型**。

**2. 黄辉祥、程坤《分类有序、片区化推进乡村振兴的理论逻辑与实践进路》**

强调「分类有序」是政策前提；并引《乡村振兴战略规划（2018—2022 年）》的村庄四分类
（集聚提升类、城郊融合类、特色保护类、搬迁撤并类）。这提示：**村庄禀赋类型**应作为片区的一个属性维度，
而不是片区类型本身。

**3. 廖敏伶、李明《片区化推进乡村振兴的理论逻辑、典型模式和制度安排》**

把「模式」与「制度安排」分开讨论——对应到数据，就是**发展模式**与**设立/治理制度**应分字段。

**4. 浙江实践的 5 种典型模式**（长江文库检索页归纳）

标杆引领+资源辐射型、产业融合+链条延伸型、要素集聚+平台赋能型、文化活化+遗产赋能型（另含综合型）。
这是把「机制」与「主题」组合起来的写法，适合做**主题标签 + 组织标签**的组合编码。

**5. 政策口径**

《乡村振兴战略规划》四类村庄；「十五五」规划纲要「分类有序、片区化推进乡村振兴」——
说明官方话语本身是「分类」而非「单一类型」，多维编码与政策文本兼容。

## 三、建议的编码（多维，不改 area 主键）

保留 `type_code` 作历史兼容，新增以下可空字段（先派生、后人工补）：

| 字段 | 含义 | 取值（封闭枚举） | 来源 |
|---|---|---|---|
| `name_type` | 命名类型 | 示范片区 / 产业片区 / 文旅片区 / 综合片区 / 片区组团 / 联合党委 / 其他 | 现有 T 码 + 名称 |
| `combo_mode` | 组合方式 | 村村联合 / 村企联合 / 村社联合 / 纵横交互 / 未知 | 郭红东（2026） |
| `group_form` | 组合质态 | 外延型 / 内涵型 / 未知 | 郭红东（2026） |
| `themes` | 功能主题（多值，逗号分隔） | 产业联动 / 文旅融合 / 生态优先 / 文化活化 / 治理创新 / 城乡融合 / 帮扶协作 / 兴边富民 / 数字赋能 | 郭红东 + 浙江 5 模式 |
| `lead_industry` | 主导产业 | 种植 / 养殖 / 加工 / 文旅 / 康养 / 电商 / 综合 / 未知 | 名称与 cover |
| `operator` | 运营载体 | 强村公司 / 合作社 / 联营公司 / 管委会 / 无 / 未知 | cover/summary |
| `governance` | 治理结构 | 联合党委 / 片区管委会 / 强村公司 / 联席会议 / 无 / 未知 | cover/summary |
| `village_class` | 村庄禀赋类型 | 集聚提升 / 城郊融合 / 特色保护 / 搬迁撤并 / 混合 / 未知 | 政策四分类（黄辉祥文引用） |

设计原则：

1. **一个字段只回答一个问题**（命名 ≠ 主题 ≠ 组织 ≠ 质态）；
2. 主题多值，允许「产业联动+文旅融合」并存；
3. 未知一律显式 `未知`，不猜；
4. 新增字段不参与 `area_caliber` 口径判定，避免一改类型就动统计。

## 五、落地步骤

**阶段 1（约 1 天，不动统计）**
1. `docs/02` 增补字段定义；`build_db` 加列（可空）；
2. 新脚本 `derive_area_dimensions.py`：按第四节映射 + 名称关键词派生 `name_type/themes`，覆盖率写入报告；
3. 校验：`validate_db` 只检查枚举值，不强制非空。

**阶段 2（前端，约 1 天）**
4. 检索页类型列改为「命名类型 + 主题 chips」，新增主题筛选；
5. 首页/方法页增加「主题分布」条形（替代现有 T 码图）；
6. 省页可显示该省主题构成。

**阶段 3（补全，按需）**
7. 子智能体按省读 `cover_desc/summary`，补 `combo_mode/group_form/operator/governance`；
8. 覆盖率达到 60% 后，把 `themes` 纳入分析视图 `v_analysis_area`。

**阶段 4（退役 T 码）**
9. `type_code` 保留为 legacy 字段，统计与前端全部改用新维度；T03 在 `area` 里的残留一并清掉。

## 六、验收标准

- `name_type` 100% 有值、`themes` 至少 1 个值；
- 主题分布不再出现「T01 占 54%」这种把命名当类型的失真；
- 任一片区可同时被标为「产业联动 + 文旅融合」；
- 口径统计（A–E、M/P）不因类型学改动而变化（可用 `check_doc_caliber` 断言）。
