# 媒体与融媒线索采集：可行性实测（2026-11）

> 目标：用公众号/融媒等非政府渠道，为「零单元县」找片区线索。
> 工具：`scripts/media_leads.py`（搜狗微信 + 搜狗网页，公开只读、匿名、限速）。
> 结论：**通道有效但被强限流，不是工具问题。**

## 一、实测数据

| 指标 | 结果 |
|---|---|
| 试跑 | 12 个县 → 抓 119 条结果，命中 **18** 条线索，覆盖 **8** 个县（67%） |
| 扩量 | 又跑 60 个县 → 前 50 个正常，**第 51 个起大量返回 0 条** |
| 定位 | 单条请求返回 `antispider` 验证页 → **IP 级反爬已触发** |
| 单县成本 | 约 5 秒（1 查询 + 3 秒间隔）；放慢到 6 秒后更稳 |
| 限流阈值 | 实测约 **50–60 次请求**即触发，冷却时间未知（20 秒不够） |

当前已收 **28 条线索，覆盖 11 个县**（`data/stage/candidates/media-leads-2026-11-18.csv`）。

## 二、线索质量：必须两道过滤

第一版按「县名前两字」匹配，出了两类脏数据，已改为全名匹配 + 语境排除：

| 问题 | 例子 | 处理 |
|---|---|---|
| 前两字误命中 | 查「珠山区」命中青岛「灵**珠山**街道」 | 必须出现**全名**（含县/区/市后缀） |
| 城市开发语境混入 | 濂溪区命中「6 个片区土地**成片开发**」「土地**征收**」 | 命中即丢弃：成片开发/土地征收/控规/产业园/开发区/棚户区等 |

有效线索长这样（沁水县）：六大农旅片区、沁河古堡片区、郑庄片区；
浮梁县：西线片区、六大片区（含「界田小村」等具体名）。

## 三、所以「全国 2334 个县全铺」做不到，原因不是工具

按实测速率与限流：

- 纯请求时间：2334 县 × 约 6 秒 ≈ **4 小时**
- 但每 **50–60 次请求**就被封，之后需要较长冷却，实际可用吞吐远低于此
- 单一 IP 硬跑的结果是「跑一半被封，后一半全是 0 条」——比不跑更糟，因为会误判成「该县无实践」

**这是检索通道的物理边界，不是算法能绕过的。** 绕过反爬（换 IP、轮换 UA、模拟点击）不做，
既违反 `docs/03` 的「不绕过风控」，也会把线索质量拖进不可控。

## 四、可执行的三段式方案

| 段 | 做什么 | 规模 | 产出 |
|---|---|---|---|
| 1（优先） | 用**已有证据在手的 131 个县**逐份精读 | 131 县 | 直接建档，不经媒体通道 |
| 2 | 媒体通道**分批**跑 B 档省（粤豫冀鄂湘闽赣等县多的省），每批 ≤50 县、间隔 ≥20 分钟 | 目标 300–500 县 | 线索表，供段 3 使用 |
| 3 | 对线索命中的县，回 `.gov.cn` 站内检索确认 | 按线索数 | 唯一能进 policy 层的路径 |

顺序不能倒：**媒体通道只负责「告诉你该去哪个县找」，`.gov.cn` 才是证据。**

## 五、脚本用法

```powershell
# 单批：从缺口清单第 N 个县开始，跑 50 个
& $env:MIMO_PYTHON scripts/media_leads.py --from-code 0 --limit 50 --channels sogou-wechat

# 指定县码
& $env:MIMO_PYTHON scripts/media_leads.py --counties 140521,360222

# 命中反爬会自动冷却 90 秒、连续 3 次则中止并提示续跑位置
```

产出 `data/stage/candidates/media-leads-{date}.csv`，按（县码 + 标题）去重合并，
多次运行不覆盖。

## 六、一条边界提醒

公众号与县级融媒**不是 `.gov.cn`**，按 `docs/07` 白名单不得进 `policy` 层；
进 `source` 也只能支撑 `待核` 或 `mention`。所以这批线索的价值是**缩小检索范围**，
不是直接增加库里能分析的片区数。
