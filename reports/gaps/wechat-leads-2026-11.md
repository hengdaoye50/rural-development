# 公众号搜索通道接入报告（2026-11）

> 目的：用微信公众号公共搜索补充片区线索。
> 工具：`yichen-unified-search`（已安装）+ 本项目补写的两个脚本。
> 结论：**通道可用，但只到「线索」层，到不了「证据」层。**

## 一、Skill 安装与路线可用性

`yichen-unified-search` 已装到 `~/.config/mimocode/skills/yichen-unified-search`（34 个文件，
只读、匿名、不含凭证）。它的离线路由器可用：

```
python scripts/route_search.py --query "..." --platform wechat --mode search --limit 10
→ status=ready, backend=opencli-weixin-public, 单一执行步骤 opencli weixin search
```

但**它的原生公众号路线在本机跑不起来**：

| 环节 | 状态 | 原因 |
|---|---|---|
| 路由器（离线） | ✅ 可用 | status=ready，正确给出执行步骤 |
| `opencli doctor` | ❌ | Daemon not running、Extension not connected、连通性测试失败 |
| `opencli weixin search` | ❌ | 依赖 Browser Bridge（daemon + 浏览器扩展），本机无 |
| 搜狗结果页直读 | ✅ 可用 | HTTP 取 `weixin.sogou.com` 结果页能拿到标题/摘要/日期 |
| 打开文章正文 | ❌ | 搜狗 `/link?url=` 跳转被反爬拦截（跳到 antispider 验证页） |

所以要解锁 skill 的完整路线，需要用户侧动作：启动 opencli daemon 并在 Chrome 里装上它的
Browser Bridge 扩展。在此之前，我用 HTTP 直读结果页实现了「发现」这一步。

补写的两个脚本：

- `scripts/wechat_leads.py` —— 抓搜狗公众号结果页，输出 `query/title/account/published/snippet/sogou_link`
  的线索表。限速 3 秒/词，只读匿名。
- `scripts/wechat_resolve.py` —— 尝试把搜狗跳转链换成 `mp.weixin.qq.com` 直链。当前对本机返回
  `antispider`，已如实记为不可用，不重试、不绕验证码。

## 二、这批线索能不能进库

**不能直接进 `policy` 层。** `docs/07` 的硬约束是「只收 `.gov.cn` 域名原文或政府公报」，
公众号不是 `.gov.cn`，无论它是县农业农村局运营的号还是媒体号。

能进的是 `source` 层（片区层第一手证据），但按 `docs/03` 的证据优先级，公众号属
「权威媒体转述」一档，只能支撑 `status=待核` 或 `mention`，不能当 `primary` 设立依据。
**换句话说：公众号能告诉我们「去找哪个片区」，不能证明「这个片区被官方设立」。**

## 四、这条通道的定位

| 能做 | 不能做 |
|---|---|
| 发现某县有哪些片区的**俗称/报道名** | 提供 `.gov.cn` 依据 |
| 拿到覆盖面、面积、村数等**散见数据**（如环常山 20 平方公里、19 个自然村） | 证明官方设立行为 |
| 交叉验证库内已有名称是否与地方叫法一致 | 读正文（跳转链被反爬拦截） |

**所以它的正确用法是「缺口定位器」**：先用公众号确认某县确有片区、叫什么，再去 `.gov.cn`
找对应文本。顺序不能反过来——先找公众号再补库，等于把媒体名当官方名，正是我们刚花两轮
清理掉的那类问题。

## 五、下一步建议

1. **先解 OpenCLI**：装 Browser Bridge 扩展并启动 daemon，`yichen-unified-search` 的
   wechat 路线就能跑满（含正文读取），比 HTTP 直读强一个量级
2. 若要继续用当前通道：按 §三 的 5 个靶子，逐个去县站找 `.gov.cn`；找到就建档，找不到就登记「查无」
3. 山东 2070 这个数优先核，它直接决定我们报山东覆盖率时的分母口径
