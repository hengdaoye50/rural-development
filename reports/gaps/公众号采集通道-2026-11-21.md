# 公众号采集通道（2026-11-21 实测）

## 结论
公众号是**当前最可能拿到县以下片区名单的渠道**，但只能做「发现 + 待核档案」，不能做政策层证据。

| 环节 | 工具 | 状态 | 说明 |
|---|---|---|---|
| 线索检索 | scripts/wechat_leads.py "省 片区 乡村振兴" | ✅ 可用 | 搜狗微信，一次 10 条，标题/摘要/日期可抓；已修 HTML 实体 |
| 正文抓取 | scripts/wechat_fetch.py | ❌ 受阻 | ①mp.weixin 直连返回「环境异常」验证码；②opencli Browser Bridge 未连接（需 Chrome 装 OpenCLI 扩展） |
| 名单抽取 | agent + write JSON | ✅ 可用 | 从摘要/snippet 抽片区名与县区，落 data/stage/candidates/ |
| 建档 | scripts/ingest_area_media_roster.py | ✅ 可用 | 写 area + source，status=待核，进 M 层、不进主统计 |
| 升级 | scripts/upgrade_media_roster.py | ✅ 可用 | 拿到 .gov.cn 原文后升 primary |

- 反向：<片区名> 片区 乡村振兴（确认官方表述）

opencli browser main open <url> 即可读正文。装上后我可以批量抓正文、抽名单、建 待核 档案。

## 与口径的关系
- 待核档案**计入 M 层总量**（用户 2026-11-21 裁定），但**不进主统计 629**
- 公众号**永不进 policy**（docs/07 白名单只收 .gov.cn），只能进 source

## 实测记录（2026-11-21 下午，扩展已装）

### 可用能力
1. `opencli browser main open '<url>' --window background` → `opencli browser main extract`
   返回 `{title, content}`，正文含标题/公众号名/时间/正文，**图片是 mmbiz 链接**。
2. `scripts/wechat_fetch_urls.py --abbr SD --urls <url...>`：URL 直抓 → `data/raw/{ABBR}/{date}-{slug}/原文.md + meta.json`。
3. `scripts/wechat_batch_collect.py --preset thin|sd5|gd`：检索式批量（搜狗线索 + 抓正文），单次建议 ≤10 条检索式。

### 关键发现
- **山东第五批省级乡村振兴片区 = 102 个（新建 70 + 提升 32）**，2026-06-03 省委农办/省农业农村厅/省财政厅
  《关于做好第五批省级乡村振兴片区建设工作的通知》（鲁农组办发〔2026〕14号）。
- 但**名单正文往往是图片**（如"第五批省级乡村振兴片区建设名单公示："后直接是长图），
  纯文本只有数量。→ 公众号名单需要 **OCR 流程**（`.venv-ocr` + rapidocr），不能只抓文本。
- 搜狗「查询式」抓取成功率不稳（0/2 常见，触发反爬/风控）；**更稳的是「搜索引擎找 URL → 桥接抓正文」**。
- 单篇文章可能只列本市名单（东营 6、威海 1、利津 1），全量 102 条要靠省厅通知或长图 OCR。

### 下一步（公众号通道 SOP）
1. 用 web_search 按「省/市 + 第X批 + 乡村振兴片区 名单」找 mp.weixin URL（snippet 常含名字）；
2. `wechat_fetch_urls.py` 抓正文与图片；
3. 正文有名字 → 正则/agent 抽 `{name, county, url}`；
   正文只有图 → 下载 mmbiz 图 → `.venv-ocr/scripts/ocr_pdf.py` 或 rapidocr 识别；
4. 抽出的名单 → `data/stage/candidates/area-media-roster-{ABBR}.csv` → `ingest_area_media_roster.py`
   （`status=待核`，进 M 层、不进主统计）；
5. 找到 `.gov.cn` 原文后再升级 primary。

## 首胜：山东第五批 102 个片区（2026-11-21 晚）

**完整链路已跑通**：
1. `web_search` 找到公众号文章（「【喜报】第五批省级乡村振兴片区建设名单公示」）；
2. `wechat_ocr_images.py` 用 OpenCLI 桥打开文章、读 `img[data-src]`、下载 14 张长图；
3. `.venv-ocr` 的 rapidocr 逐图 OCR（8 张有效，2073 字），**识别出完整名单：16 市 × 102 个片区**；
4. `parse_sd5_roster.py` 解析成候选表（县区按「市级前缀+名称」匹配，9 个功能区别名映射）；
5. `ingest_area_media_roster.py SD` 入库：**86 条新建待核档案 + 16 条同名已在库**。

**校验**：解析结果 新建 70 + 提升 32 = **102**，与官方「70 新建 + 32 提升」完全吻合 —— OCR 未漏条。

口径影响：M 层 1462 → **1548**（待核 322 → 408），山东 257 → 343；主统计不变（待核不进）。
后续：找到 `.gov.cn` 通知全文即可把这 86 条从待核升为 `运行中`。
