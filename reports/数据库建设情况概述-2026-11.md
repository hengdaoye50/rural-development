# 数据库建设情况概述（2026-11）

> 一句话：**政策全文层已完备，片区实体层是建档式抽样，空间锚定是主要短板。**
> 全部数字来自 `scripts/report_db_stats.py`（快照 2026-11-18），可重跑。

## 一、建的是什么

**建成对象**：中国大陆 31 个省级单位、县/区以下、以「片区」为单位推进乡村振兴的实践。
**计量单位**：一次「命名 + 设立动作」的可核验记录——不是「片区实体的一生」，也不是「官方累计投入计数」。
这个选择决定了后面所有边界：提升、更名、撤销不计为新记录；跨层重复命名按命名事件分别计。

**七层数据结构**：

```
region（区划）── area（片区）── area_policy_map（政策依据）── policy（政策全文）
      │            │
      │            ├── event（生命周期事件）
      │            ├── source（第一手证据 + 本地快照）
      │            └── area_region_map（空间归属）
      └── belt（象征单元：示范带/圈/廊，单列不并入）
```

## 四、边界在哪（必须照写）

1. **不是全国普查，是建档式抽样。** 完整度由采集覆盖决定，不由现实决定。
2. **全国/全省总量不可得。** 山东官方「省市县累计 2 070 个」是三级累计投入计数，含提升与跨层重复命名，与本库单位不可通约。
3. **重复建设与撤销不可测。** 提升、更名多不单独发文；库内 455 个片区有事件，撤销 0 条。故记录单位定为「命名事件」而非「实体一生」。
4. **检索通道覆盖不均。** 部分省级站检索失效、县级站 JS 渲染；搜狗约 50–60 次请求触发反爬。

## 六、一句话结论

**证据侧已可发表，实体侧可用于机制类型学，暂不可用于全国分布推断。**
每个数字都能回查到 `area_id`/`policy_id` 及原文路径与哈希——这是本库与「政策汇编」的根本区别。
