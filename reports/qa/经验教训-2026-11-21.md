# 采集与入库经验教训（2026-11-21，市级层第一轮）

> 适用场景：用智能体集群批量核「市级名单」→ 抽名单 → 入库 → 同步口径。
> 目的：下一轮直接照 SOP 跑，不再重复踩坑。数字均为本轮实测。

## 0. 一句话结论

**时间主要花在「返工」而不是「采集」上**：40 市扫描一次跑完约 45 分钟，
但结果没落盘、CSV 写坏、县区错配、口径同步来回修，额外多花一倍以上。
下一轮三个硬要求：**产出落文件、写盘原子化、县区带前缀匹配**。

## 1. 智能体集群的坑（6 条）

| # | 坑 | 现象 | 改法 |
|---|---|---|---|
| 1 | `pipeline(items, {label})` 用法错 | `WorkflowError: stage 1 is not a function`，整个工作流失败 | 第二参数必须是 stage 函数；简单场景用 `parallel(items.map(x => () => agent(...)))` |
| 2 | 子智能体并发上限 **8** | 40 个 `parallel` 报 `subagent limit reached`，**整个工作流失败**（不是返回 null） | 任务分片，**6 个/批串行**；每批 `await parallel(chunk)` |
| 3 | 工作流返回值**不落盘** | 第一轮 6 市抽取只把 JSON 返回到对话，长结果还被截断，无法复用，只能重跑 6 个 agent | 让 agent 自己 `write` 到 `data/stage/candidates/xxx-{code}.json` 并返回 `file_path`；根 agent 只读文件 |
| 4 | job_output 会截断长结果 | 3 个专项输出被截断，结论丢失，只能重跑 | 同上：要复用的产出必须落文件 |
| 5 | agent 的「建议状态」偏高 | 找到页面就建议 `matched`，但当时一条都没入库 | 根侧规则：`matched` 仅当条目已入库并挂接，否则降 `partial`（已写进 `apply_city_roster_scan.py`） |
| 6 | agent 的 note 太长 | 单条 800–1500 字，CSV 被撑爆 | 要求 note ≤120 字，细节放 `evidence_excerpt`/证据文件；入库脚本硬截断 600 字 |

提示词必须写死三条：只认 `.gov.cn`（媒体只作线索）；先判对象层级（示范村/乡镇/整县试点 → `not_area`）；找不到就 `found=false`，禁止编造名称/数字/URL，摘录必须逐字。

## 2. 数据入库的坑（8 条）

| # | 坑 | 现象 | 改法 |
|---|---|---|---|
| 1 | **CSV 非原子写** | 更新 dict 多了一个表头外字段，`writerows` 中途抛错，**40 行台账被写成 1 行** | 写盘用「临时文件 + `os.replace`」；写前断言 `set(row) <= set(fieldnames)` |
| 2 | **县区同名跨市** | 枣庄「市中区」匹配到济南市市中区（370103），错 2 条 | 查询 `region` 必须 **(city 前 4 位 + 名称)** 双重匹配 |
| 3 | **功能区无县级码** | 烟台潮水镇（黄渤海新区）`370600` 被拒（只收 level=county） | 别名表：黄渤海新区→蓬莱 370614、西海岸新区→黄岛 370211、常州经开区→武进 320412、泰安高新区→岱岳 370911 |
| 4 | **政策要先入 master** | 新政策只在 by_province，`ingest_area_roster` 查 master 报「p 不在 policy 表」 | 固定顺序：`ingest_policy → merge → build → ingest_area_roster → merge → build` |
| 5 | **policy_id 不可机读** | `ingest_policy` 只打印 ID | 从 `by_province/{ABBR}-policy.csv` 按 doc_no/title 反查 |
| 6 | **fetch_gov_doc 只吃 HTML** | docx/PDF 附件里的名单抓不到（页面正文仅 339/505 字） | docx = zipfile 读 `word/document.xml` 去标签；PDF = `.venv-ocr` 的 pypdfium2；扫描页 = rapidocr |
| 7 | **相对链接无前导 /** | 淄博 docx 直接拼域名失败 | `urllib.parse.urljoin(页面URL, href)` |
| 8 | **派生 source 无快照** | 新 source `local_path` 空 → validate 新增 warning | 把派生 source 的 local_path/hash 指到政策原文，by_province + master 两处同改 |

## 3. 文档口径与 git 的坑（4 条）

| # | 坑 | 现象 | 改法 |
|---|---|---|---|
| 1 | 一次入库动 **40–55 处**数字 | 每次都要改 README/docs/00/01/09/HANDOVER | 两步走：先跑 guard 拿清单 → 行级上下文替换 → 再跑 guard 修尾 |
| 2 | guard 未覆盖的行 | 「A 行」「N = 」「1 324（空格分位）」无关键词，替换漏掉 | 用 `.py` 精确替换；**禁止在 PowerShell here-string 里写含反引号的字符串** |
| 3 | `git add -A` 扫进临时脚本 | `.tmp-scan/*.py` 被提交，事后要 `git rm --cached` | `.gitignore` 加 `.tmp*/`；提交前看 `git status` |
| 4 | 新候选 JSON 被 ignore | `city-extract-*.json` 加不进 | `.gitignore` 加 `!` 例外 |

## 4. 下一轮 SOP

```powershell
# A. 名单扫描（6 个/批）；agent 写 city-extract-{code}.json 并返回 file_path
python scripts/apply_city_roster_scan.py <scan.json>

# B. 单市入库（HTML 页面）
python scripts/fetch_gov_doc.py --out data/stage/batches/POL-{ABBR}-city{code}-policy.jsonl `
  --doc "url=...,title=...,issuer=...,issuer_level=city,doc_type=名单,published_ymd=...,province_code=...,city_code=..."
python scripts/ingest_policy.py data/stage/batches/POL-{ABBR}-city{code}-policy.jsonl
python scripts/merge_by_province.py ; python scripts/build_db.py
python scripts/build_city_rosters.py {code}
python scripts/ingest_area_roster.py {ABBR}
python scripts/merge_by_province.py ; python scripts/build_db.py
python scripts/validate_db.py ; python scripts/health_report.py ; python scripts/check_doc_caliber.py

# C. 附件型：docx/PDF/扫描页先抽全文 -> 手写 batch jsonl -> ingest_policy
# D. 收盘：report_city_roster / report_province_roster / report_macro_layer /
#    report_level_distribution / report_db_stats / report_corpus_overview / case_pool
#    然后数字同步 -> guard -> git add（别用 -A）-> commit -> push
```

## 5. 本轮沉淀的脚本

| 脚本 | 作用 |
|---|---|
| `apply_city_roster_scan.py` | 扫描结果 → `city_roster`（含 matched→partial 降级、note 截断） |
| `build_city_rosters.py` | `city-extract-{code}.json` → 候选表（县区按「城市前缀+名称」匹配） |
| `report_province_roster.py` / `report_city_roster.py` | 省/市台账报告（现算关联数、标 ⚠） |
| `ingest_area_media_roster.py` | 媒体名单建档（不建 policy、status=待核） |
| `upgrade_media_roster.py` | 官方原文出现后，媒体名单批量升级为 primary |

## 6. 已知遗留

- 广东 130 条：官方域名确认无原文（仅县区转引 16 条），维持待核；
- 浙江：官方只有「省级重点村名单」（村层），200/500 是目标数，不存在片区名录；
- `city_roster` 仍是 40 市（浙苏鲁），其余 293 个地级行政区未扫；
- `partial` 16 市已定位名单但未入库，济宁 96、金华 60、宁波 20 价值最大；
- guard 未覆盖案例池等非核心数字，仍需手工顺带更新。
